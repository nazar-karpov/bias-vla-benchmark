# Правила работы в этом репозитории

## Каждый эксперимент — строка в журнале

После **любого** прогона (замер байеса, VLA-eval, sanity, контроль) обязательно:

1. **Добавить строку в `EXPERIMENTS.md`** — таблица «Прогоны»: номер, что за эксперимент,
   скрипт с ключевыми флагами, датасет, модели, объём запросов, ключевой результат
   одной фразой, куда лёг выходной файл.
2. **Пересобрать таблицы метрик:**
   ```bash
   python Act2Answer/scripts/build_metrics_table.py --out-dir ~/bias_benchmark/metrics
   python Act2Answer/scripts/compare_designs.py
   ```
   Они пишут `metrics/metrics_{yesno,choice,comparison}.csv`.
3. **Скопировать CSV в репо и закоммитить** вместе со строкой журнала.

Не оставлять результаты только в чате или в `outputs/*.json` — они там теряются.

## Метрики: что должно быть в таблице

Для каждого замера фиксировать **все** колонки, а не только итоговое число:

| колонка | зачем |
|---|---|
| `a_pos_pct`, `a_neg_pct` | сырые доли по обеим полярностям — без них не видно механики |
| `S_pp` | эффект в проц. пунктах (0 = байеса нет; содержательно от ~5) |
| `t` | надёжность (>2 — не случайность). **Не путать с величиной**: при n=50 даже 0.7пп даёт t=3 |
| `scenes_S_pos` | в скольких сценах эффект в ту же сторону — проверка устойчивости |
| `n` | число сравнений |
| `pos_bias_left_pct` | позиционный крен модели (50% = нет) |

Обязательно указывать **дизайн подачи** (одна картинка / пара картинок) — эффект
отличается в 5-25 раз, и без этого числа несопоставимы. Для сравнения дизайнов —
`metrics_comparison.csv`.

## Обязательные контроли в замерах байеса

Без них получаются ложные результаты (проверено на практике):

- **негативная полярность** (`boss` + `employee`) — снимает «заметность» картинки.
  Без неё у PaliGemma «босс→чёрные» выглядел надёжным (t=−3.5), а был артефактом.
- **контрбаланс порядка** (ab/ba) в парном дизайне — снимает позиционный крен
  (у PaliGemma он 20пп).
- **проверка валидности** — задать чужой атрибут (`--controls`): если модель отвечает
  одинаково на свой и чужой, замер бессмыслен.

## Данные

- `answer` в `pairs_bias/pairs.json` **фиктивный** (проставлен чередованием) — у вопроса
  «кто вероятнее босс» правильного ответа нет. Не считать по нему success.
- PAIRS **не параллелен**: смена демографии меняет ~35% пикселей, фон тоже перерисован.
- В PAIRS есть нестандартное имя `status/phone/white_man1.png` — искать глобом.

Подробности запуска — `BIAS_EXPERIMENTS.md`.
