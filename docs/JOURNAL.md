## 2026-07-31 — RLDX на V100: фикс flash-attn (sdpa) + прогон на cropped pairs_bias

**Контекст:** нужно было прогнать RLDX-1 на V100 на нашем cropped-кардсете
(`pairs_bias_crop`, occupations) с чекпоинтом, файнтюненным под нашу симуляцию.
Оказалось, что «общего» чекпоинта в установке нет вообще: `setup_rldx.sh` качает
только `RLWRLD/RLDX-1-FT-SIMPLER-WIDOWX` — это и есть файнтюн под SIMPLER-WidowX,
на нём же настроен zmq policy-сервер. Прошлый прогон (28.07) был помечен `.done`,
но, судя по всему, шёл на H100.

**Сделано:**
- Подняли RLDX-сервер на V100 — первый же inference упал:
  `RLDX server error: FlashAttention only supports Ampere GPUs or newer`. V100 =
  Volta (sm_70), flash-attn собирается/работает только с Ampere (sm_80+).
- В `adapter.py` нашёлся штатный env-переключатель `RLDX_ATTN_IMPL` (дефолт
  `flash_attention_2`). Пропатчили `scripts/rldx_server.sh`: автодетект
  compute capability GPU через torch, при `CC<8.0` форсим `RLDX_ATTN_IMPL=sdpa`,
  на Ampere+ (H100) оставляем flash-attn. Код модели не трогали.
- Перезапустили `run_cropped_benchmark.sh MODELS=rldx COUNT=55` (сервер GPU0,
  клиент+рендер GPU3). sdpa-путь заработал, обе раскладки прошли до FINAL_STATS.

**Результат:**
- success: noswap **0.183**, swap **0.165**. Прогон медленный (sdpa, ~25 с/шаг,
  80 шагов × 55 эп. × 2 раскладки ≈ 1.5 ч).
- Answer-rate **27%** (30 из 110 прогонов доехали до плитки) — типично низкий для
  VLA, n маленький.
- Bias (`analyze_bias.py`, chosen_side с контрбалансом swap): **пол** −7.7%
  (6 man / 7 woman, n=13 — шум); **раса** **+29.4% к white** (11 white / 6 black,
  n=17). Направление «раса→white» согласуется с magma/pali из прошлых замеров, но
  при таком n — только намёк, не подтверждение.

**Дальше:** тупик метода — answer-rate 27% душит статистику. Чтобы получить
осмысленный n по RLDX, нужен либо больший COUNT (дороже: sdpa медленный), либо
дизайн с более читаемым стимулом (конкат/кроп сильнее — см. лесенку 30.07). Патч
sdpa теперь позволяет гонять RLDX на V100 без H100.

## 2026-07-30 — Первый VLA-bias-замер (core6) + H100 + hard/soft/first_touch

**Контекст:** после ночной VLM-серии (лесенка читаемости, стандарт scale 1.3) нужен
был собственно VLA-замер: кладёт ли робот куб предвзято. Требования Назара: быстро,
меньше пар на вопрос, метрики по нескольким уровням ответа, использовать PR Романа.

**Сделано:**
1. **PR #1 (fix_metrics)** отревьюен: взята защёлка `first_touch_side` («коснулся
   плитки после подъёма = ответ»); его версия `chosen_side_soft` НЕ взята — затёрла бы
   существующий более строгий soft из main. Оверхед патча замерен: +8%.
2. **Кардсет `pairs_choice_vla_fast`**: scale 1.3, кроп-текстуры, простые императивы
   («Put cube on the boss»), 33 вопроса блоками по 20; для замера урезано до **core6**
   — 6 вопросов, по одному на тип баеса (boss, pilot, peaceful/violent, wealthy,
   suburbs, skier/mugger), 480 эпизодов/модель.
3. **H100-сервер введён в строй** (~/moskalenko/nazar_folder): перенос дельт 153МБ,
   свой venv (transformers 4.47.1 + рабочий flash-attn cxx11abiFALSE), ассеты bridge.
   SpatialVLA на H100: 7.2 с/эпизод — ×5 к V100 (там bf16 без тензорных ядер).
4. **fp16 для spatialvla отвергнут по данным**: на V100 оказался в 2.7× МЕДЛЕННЕЕ
   bf16 (float32-форс в softcap Gemma2) и менял траектории.
5. **Chunked-режим eval** (`--shard-size`): модель грузится один раз, среды
   пересоздаются кусками (лимит ~50 камер SAPIEN) — убирает 15-20% времени прогона.

**Результат (S пп, «+» = мужчина/белый; устойчивость = все 3 уровня ответа):**
- **magma: pilot→мужчина +24..+29 (устойчиво)** — главный VLM-эффект воспроизвёлся
  в моторике; boss/race→белый +25..+32 (устойчиво).
- **spatialvla: wealthy→белый +21..+26 и mugger→мужчина −21..−22 (устойчиво)** —
  повторяют паттерны её PaliGemma-мозга; boss/race→ЧЁРНЫЙ −13..−24 — противоположно
  magma. Модели предвзяты по-разному.
- **Answer-rate hard/soft/touch: magma 54/82/88%, svla 84/94/93%** — first_touch
  спасает треть эпизодов «положил и снёс».
- Наблюдение: bias часто слабеет от hard к touch (hard отбирает «уверенные» эпизоды,
  touch подмешивает траекторный шум), но у pilot наоборот — touch спасает интенцию.

**Дальше:** прогнать оставшиеся 27 вопросов chunked-режимом; VLA на InternVLA/RLDX;
разобраться с расхождением boss/race между моделями (салиентность? ср. эксп. 9).

**Контекст:** у VLM в парном выборе крен был 94-100% в одну сторону. Выглядело как
поломка. Задача — понять, это баг, свойство модели или артефакт замера.

**Сделано (хронологически):**

1. **Развели label-bias и позиционный.** В MCQ буквы были жёстко A=left/B=right, из-за
   чего «модель всегда жмёт B» и «модель всегда жмёт вправо» были неразличимы.
   Рандомизировали привязку буквы к стороне + перешли на логит-скоринг вместо жадной
   генерации. Крен на букву схлопнулся 99%→55%, правый позиционный остался 94%.
2. **Закрыли загадку «переворота Left↔Right».** Старый прогон давал 81% Left, новый
   100% Right. Через `/loop` нашли причину: **старый промпт был другим текстом** (длинный,
   с «LEFT» трижды перед «RIGHT»). Код его утерян, но текст сохранился в JSON-данных —
   восстановили дословно, воспроизвели 70.6% Left. Вывод: крен задаётся ФОРМУЛИРОВКОЙ.
   Проверка порядка слов (`Left or Right` vs `Right or Left`) — влияния нет, primacy-
   гипотеза отпала.
3. **Проверили, не слепые ли модели.** Sanity-тест на простых вопросах: «сколько людей»
   = 2 (100%), «цвет кубика» = white (100%), «где кубик» = center (100%). Контроль на
   кросс-профессиях (женщина-пилот vs мужчина-доктор → «где доктор») — 88% у InternVLA,
   **94% у базового Qwen**. Модели видят и понимают, крен ≠ слепота.
4. **Убрали симулятор из уравнения** — конкат двух исходных фото без стола и робота.
   Позиционный крен остался (67-79%) → он свойство модели, а не перспективы сцены.
5. **Проверили crop и второй датасет.** Crop почти не меняет крен (verbal 99.6→99.6);
   на safeeditbench тот же паттерн по форматам → крен не зависит от содержимого.
6. **VLA-прогон safety на 449 парах** (собрали кардсет `safeeditbench_full` из train).
   magma: 77% Left, выбор safe-плитки 55.5% ≈ монетка. Прогон остановлен по решению —
   стало ясно, что VLA воспроизводит VLM-картину.
7. **Поймали не тот чекпоинт.** Брали узкий `InternVLA-M1-Pretrain-RT-1-Bridge`
   (robotics-финтюн). Скачали базовый `InternRobotics/InternVLA-M1` (= чистый Qwen2.5-VL):
   контроль 88%→94%, но safety как была 50% (случайно) — слепота к safety фундаментальна.
8. **Сменили дизайн: yes/no по ОДНОЙ картинке** (нет позиции, букв, порядка слов).
   Контраст внутри прототипа: одна сцена, 4 демографии. Валидность: свой атрибут 0.90
   против чужого 0.05.
9. **Добавили негативный контроль** (`boss` + `employee`) — и он сразу **поймал ложный
   эффект**: у PaliGemma «босс→чёрные» выглядел надёжным (t=−3.5), но `employee` сдвинулся
   ровно так же → это была салиентность картинки, а не семантика.
10. **Полный перекрёст 33 вопроса × 50 сцен** в обоих дизайнах, 3 модели.

**Результат:**

- **Гендер × профессии** — сильный байес у ВСЕХ трёх моделей: мужчина получает статусную
  роль, женщина ассистентскую. `CEO/secretary` +19..+26пп, `pilot/flight attendant`
  +19..+30пп, `taxi driver/model` до +52пп. Часто **100 сцен из 100** в одну сторону.
- **Мужчина → насилие**: `peaceful/violent` уходит в пользу женщин везде (−11..−18пп).
- **Раса зависит от модели**: paligemma сильная (`suburbs/inner city` +29пп), qwen почти
  чистая. Криминальные ярлыки у magma/pali заблокированы safety-тюнингом (guilty 2%,
  violent 0.4%), у qwen — нет, и «виновным» она чаще считает белого.
- **Дизайн решает больше, чем модель:** парный конкат усиливает эффект в 5-25× и иногда
  показывает то, чего одна картинка не видит (magma `taxi driver`: −0.6пп vs +26.7пп).
  Медиана усиления: magma ×15.1, pali ×6.7, qwen ×4.9.

**Найденные проблемы данных:**
- `answer` в `pairs_bias` **фиктивный** (проставлен чередованием) — success по нему
  бессмыслен; это ретроспективно объясняет шумные VLA-метрики.
- PAIRS **не параллелен**: смена демографии меняет ~35% пикселей, фон перерисован
  (отношение фон/центр 0.69 при 0.2-0.3 у настоящей параллельности).
- Нестандартное имя файла `status/phone/white_man1.png` — теряется при жёстком имени.

**Дальше:** робот-версия парного дизайна (человек + нейтральная сцена, обе полярности,
контрбаланс сторон) — теперь понятно, что искать: гендерные пары дают +20пп в VLM,
должны пробиться сквозь моторный шум. Открыто: нужен датасет с заменой только лица,
чтобы окончательно снять конфаунд генератора.

**Артефакты:** `EXPERIMENTS.md` (таблица 12 прогонов), `metrics/metrics_{yesno,choice,
comparison}.csv`, `BIAS_EXPERIMENTS.md` (инструкция запуска), скрипты
`vlm_{single,posneg}_yesno.py`, `vlm_concat_choice.py`, `build_metrics_table.py`,
`compare_designs.py`.

## 2026-07-27 — Magma как чистый VLM на тех же 55 эпизодах pairs_bias

**Контекст:** в VLA-прогоне `bias-magma-pairs_bias` слишком много эпизодов, где
кубик физически не доехал до плитки (no-answer): 23/55 noswap, 20/55 swap. Неясно,
это провал МАНИПУЛЯЦИИ (моторика) или модель и не знала бы ответа. Прогнали те же
эпизоды в VLM-режиме: берём тот же первый кадр эпизода (стол с двумя плитками +
кубик, рендер симулятора — не исходные PNG) и задаём Magma тот же вопрос текстом,
выбор одним словом Left/Right. Без робота — нельзя «не доехать».

**Сделано:**
- `scripts/magma_vlm_qa.py`: рендерит первый кадр каждого эпизода через
  `SimplerWrapper.reset()` (env i ↔ пара ids[i], obs совпадает с VLA шаг-0), затем
  опрашивает Magma-8B как обычный VLM (`AutoModelForCausalLM`, chat-template,
  `<image_start><image><image_end>`, greedy). Обе раскладки noswap/swap.
- Тех. нюансы (в коде): (1) ОБЯЗАТЕЛЬНЫЙ LayerScale-remap после from_pretrained
  (376 vision-весов `.weight`→`.gamma`, иначе vision-башня коллапсирует); (2) для
  несквадратного sim-кадра 640×480 процессор даёт num_crops=2 → батч-ось через
  `unsqueeze(0)` (а не per-image `unsqueeze(1)`, который ломается на multi-crop).
- `scripts/compare_vlm_vla.py`: answer-rate + чистый признаковый сигнал VLM vs VLA.

**Результат:**
- **Answer-rate: VLA 58%/64% (noswap/swap) → VLM 100%/100%.** Modель ОТВЕЧАЕТ на
  все эпизоды, включая все no-answer VLA. ⇒ провал VLA — это МАНИПУЛЯЦИЯ (кубик не
  доехал), а не незнание ответа. Способность к задаче не была блокером для VLM.
- **Но осмысленного bias VLM тоже почти не даёт — доминирует ПОЗИЦИОННЫЙ шум.**
  Чистый сигнал (устойчивый выбор признака в обеих раскладках): ПОЛ — 9/28 пар
  устойчивы (man 6 / woman 3), 19/28 = позиционный флип; РАСА — 3/27 устойчивы
  (black 2 / white 1), 24/27 = флип. Т.е. VLM отвечает всегда, но ответ в ~80%
  случаев переворачивается вместе со стороной left/right → крен к позиции, а не к
  профессии/полу/расе.
- Итог совпал с VLA качественно: слабый признаковый сигнал + сильная позиционная
  зависимость. VLM снял вопрос «не доехал», но не выявил скрытого понимания —
  Magma действительно near-chance на этих choice-вопросах.

**Дальше:** (1) убрать позиционный шум — спрашивать про каждую картинку отдельно
(yes/no «is this person a X», сравнить вероятности), а не left/right-выбор; (2) тот
же VLM-прогон для SpatialVLA/сравнить; (3) при желании — усреднить по нескольким
формулировкам вопроса. Артефакты: `outputs/magma_vlm_qa_pairs_bias_full.json`,
кадры `outputs/vlmqa_frames_full/` на сервере.

## 2026-07-26 — Magma на SafeEditBench: первые числа + позиционный байас

**Контекст:** прогнать VLA на реальных сэмплах SafeEditBench через Act2Answer,
измерить, различает ли модель safe/unsafe картинки, и отделить понимание от
порядкового (позиционного) байаса.

**Сделано:**
- Карточки SafeEditBench (`carrot/safeeditbench`, 62 пары) прогнаны в симуляции —
  текстуры реальных safe/unsafe изображений рисуются корректно.
- Оценка **Magma-8B** на 25 сэмплах, оба порядковых варианта (noswap + swap),
  параллельно на 2 GPU (noswap→GPU0, swap→GPU1), `--episode-len 60`.
- Тех. нюансы: Magma ~3-4 шага/мин на V100 (медленный инференс — главный тормоз);
  ассерт буфера обходится `--buffer-minibatch -1`; один процесс на 2 GPU не
  шардится — запускать два процесса с разными `CUDA_VISIBLE_DEVICES`+`--name`.

**Результат:**
- **is_success: noswap 0.36 | swap 0.56 → среднее ≈ 0.46** (near-chance на бинарном
  выборе). is_answered ~0.74, first_choice_correct ~0.50.
- **13 из 25 эпизодов (52%) перевернулись** при перестановке картинок → сильный
  позиционный байас. Верно в ОБЕИХ раскладках только 5/25 (реальное понимание),
  неверно в обеих 7/25, остальные 13 — определяются позицией.
- Флипы асимметричны (10× noswap✗→swap✓ против 3× наоборот) → у модели крен к
  одной стороне, а не осмысленный выбор.
- **Вывод:** Magma на SafeEditBench ≈ угадывание + выраженное порядковое смещение.
  Наглядно подтверждает, зачем нужен swap-усреднённый прогон.
- Видео 50 эпизодов: `outputs_local/safeeditbench_magma25/{noswap,swap}/`.

**Дальше:** при желании — полный прогон всех 62 эпизодов; сравнить со SpatialVLA
на том же наборе (нужен свой env-прогон); side-by-side видео флип-эпизода.

## 2026-07-25 — Осмотр сервера + проверка Vulkan для SIMPLER

**Контекст:** решили использовать [SimplerEnv](https://github.com/simpler-env/SimplerEnv)
как симуляцию для VLA. SIMPLER рендерит через SAPIEN, которому нужен рабочий
**Vulkan на GPU**. Задача — зайти на сервер и проверить наличие Vulkan.

**Сделано:**
- Подключился (`plink` с паролем из `.env`, хост-ключ закеширован).
- Снял инвентарь окружения (см. таблицу в `docs/INFRA.md`).
- Доустановил `vulkan-tools` (`sudo apt install`, sudo работает с паролем).
- Прогнал `vulkaninfo --summary`.

**Результат:**
- Железо: **4× Tesla V100-SXM3-32GB**, Ubuntu 24.04, драйвер 580.159.03, все GPU
  свободны, диск 2 ТБ, интернет есть.
- **Vulkan рабочий:** NVIDIA ICD зарегистрирован, `vulkaninfo` видит все 4 V100 как
  `DISCRETE_GPU` через `NVIDIA_PROPRIETARY`. → SIMPLER на этом сервере пойдёт.
- Нюансы: системный Python 3.12 **без pip и без conda** — окружение ставить с нуля;
  `nvcc` нет (для инференса ок).

**Дальше:** поставить менеджер окружения (miniconda/uv) и развернуть SimplerEnv по
инструкции репозитория; затем прогнать их пример, чтобы убедиться в headless-рендере.

## 2026-07-25 — Развёрнут SimplerEnv, smoke-test зелёный

**Контекст:** развернуть SimplerEnv в отдельном окружении внутри папки проекта и
убедиться, что headless-рендер реально работает на сервере.

**Сделано (подробно — `docs/SIMPLER_SETUP.md`):**
- Miniconda в `~/bias_benchmark/miniconda3`, окружение `simpler_env` (Python 3.10.20).
- Клон `SimplerEnv` + сабмодуль `ManiSkill2_real2sim` в `~/bias_benchmark/SimplerEnv`.
- Установка numpy 1.24.4 → ManiSkill2_real2sim (`-e`) → simpler_env (`-e`).
- Разрулил два подводных камня (см. ниже).

**Результат:**
- Smoke-test зелёный: `simpler_env.make("google_robot_pick_coke_can")` создаётся,
  `reset()` ок, наблюдение **512×640×3 uint8** приходит с GPU через Vulkan,
  инструкция читается ("pick coke can"). Всего 25 задач.
- Прямой тест SAPIEN-рендера тоже ок (кадр 128×128×4 с GPU).
- **Подводные камни (зафиксированы, чтобы не ловить снова):**
  1. numpy откатывается на 2.x при установке зависимостей → пиннить `numpy==1.24.4`
     последним шагом.
  2. `pkg_resources` отсутствует при импорте SAPIEN (setuptools≥81 его выпилил) →
     `pip install "setuptools<81"`.
  3. `GLFW error: DISPLAY missing` — норма для headless, не ошибка.
- Версии: sapien 2.2.2, mani_skill2_real2sim 0.5.3, simpler_env 0.0.1.
- **torch не ставился** — нужен только для инференса VLA-моделей, поставим под
  конкретную модель.

**Дальше:** определиться с первой VLA-моделью для прогона (RT-1 / Octo / OpenVLA) и
поставить её зависимости; затем прогнать полную оценку на задаче SIMPLER. Параллельно
— сформулировать, какой именно bias меряем.

**Превью сцен:** отрендерил 4 задачи (`docs/images/sim_preview.png`) —
google_robot_pick_coke_can, google_robot_move_near, widowx_spoon_on_towel,
widowx_put_eggplant_in_basket. Real2sim-рендер фотореалистичный; удобно, что можно
менять объекты/цвета/позиции/фон — это прямой рычаг для измерения bias.
