FOCUS: 193 вопроса, 3000 пар/вопрос (500 gender + 2500 ethnicity), обе
раскладки: **1 158 000 эпизодов на модель**, без урезания объёма или банка.
Глобальный q193f остаётся **2 316 000 эпизодов на модель** (FOCUS+VisBias).
Это распределение задач на новую ноду, а не исключение VisBias из программы.
SpatialVLA/Xiaomi/GR00T FOCUS целиком принадлежат h100q13: не запускать
те же условия на других нодах параллельно без разделения диапазонов.
InternVLA прочие условия продолжают h100q10/h100q11, пересечений нет.

Старый резерв **h100q10 GPU2** сохраняется для другого эксперимента.
На неё ничего не ставили. 1536 эпизодов переведены на GPU2 новой ноды
с первого пропуска **286464**; первые сохранённые шарды до 286416 не трогали.
Живая запись старого резерва дополнена владельцем хвоста h100q13.

- Веса SpatialVLA, Xiaomi, GR00T, Cosmos-Reason2 и venv доступны на NFS;
  загрузок заново не потребовалось. Серверный venv: torch 2.9.0+cu128,

  GPU2 InternVLA 14:18:35 (клиент resume 14:20:26), GPU3 SpatialVLA 14:20:06.

  action=(48,80,7), episode_len=80. Первый шард GPU2 s286464, остальных s0.

  штатные настройки промптов, физики и readout не менялись.
- Короткий 20-секундный сэмпл GPU util: 77.2/70.8/71.3/66.3% в среднем;
  моментальная загрузка при инференсе SpatialVLA доходила до 97–100%.
  Заполнены все четыре GPU, а не только память моделей.

Узловой драйвер сделан из штатного q193f_driver.sh с индивидуальной очередью
по GPU: только GPU2 может выбирать InternVLA. Проверка цепочек и выбор задач
оба используют GMODELS, поэтому на GPU0/1/3 нет дубликатов текущего InternVLA.
Драйвер продолжает пропуски и сам переключает модели. Старт/лаунчер проверены
`bash -n`; минимальная разница с исходником сохранена как `driver.patch`.

Артефакты: plan.json, launch_h100q13.sh, driver.patch,
first_shard_validation.json, gpu_util_sample.csv / gpu_util_summary.json;
операционный CSV `metrics/q193f_h100q13_startup_20261102.csv`.
Научных выводов по четырём первым шардам не делали: для bias нужны полные
сбалансированные раунды и все контроли. Старый build_metrics_table.py снова
проверен в изолированной копии и падает на мёртвом V100-пути PAIRS;
compare_designs.py работает на сохранённых CSV. Живые научные CSV не затирались.
Полные q193f-метрики считаются q193f_summary.py по мере накопления раундов.
